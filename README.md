# 長期上昇候補スクリーナー（ローカル実行版）

株探(kabutan.jp)のデータをもとに、業績（ファンダメンタルズ）・株価トレンド（テクニカル）・
需給（信用取引）を組み合わせて「長期で上昇しやすそうな候補」をスコアリングするツールです。

これまでClaude(このリポジトリの元になった会話)が毎回スクレイピングと計算を代行していましたが、
その部分をこのローカルスクリプトに肩代わりさせ、**計算済みの結果（output/summary_latest.json）を
Claudeとの会話に貼ってコメントをもらう**運用に切り替えるためのものです。

このリポジトリには2つの独立したツールが入っています（データベース・レポートも完全に別）。

1. **長期上昇候補スクリーナー**（`screener.py` / `run.bat`）: 業績・トレンド・需給から
   長期的に上昇しやすそうな銘柄を探す（このREADMEの前半で説明）
2. **出来高急増ウォッチ**（`volume_watch.py` / `run_volume.bat`）: 出来高が急に増えたのに
   株価がまだ動いていない銘柄（＝物言わぬ買い集めの可能性）を探す（後半で説明）

## 必要なもの

- Windows / macOS / Linux のいずれか
- Python 3.9 以上（<https://www.python.org/> からインストール可能。インストール時に
  「Add Python to PATH」にチェックを入れてください）
- インターネット接続（kabutan.jpにアクセスできること）
- ディスク空き容量 約300MB（初回のみ、Playwright用Chromiumのダウンロード）

## 使い方（Windows）

1. このフォルダを好きな場所に置く
2. `run.bat` をダブルクリック
   - 初回は仮想環境(venv)の作成・依存パッケージのインストールに加え、
     ブラウザ自動操作用のChromium本体（150〜300MB程度）のダウンロードが走るため、
     数分かかることがあります（2回目以降はスキップされます）
   - 実行が終わると `output/report.html` が自動でブラウザに開きます
3. `output/summary_latest.json` の中身をコピーして、Claudeとの会話に貼り付けると
   上位銘柄や前回からの変化についてコメントをもらえます（ファイルをそのまま添付してもOK）

## なぜブラウザ(Playwright)を使うのか

当初は`requests`ライブラリで直接HTTPアクセスする方式でしたが、実際に動かしたところ
kabutan.jp側のbot対策とみられる挙動により、ページの見出し自体は見つかるのに
中身が0件になる、という症状が確認されました。そこで、ヘッドレスのChromiumを
実際に起動してページを描画させてからHTMLを取得する方式（Playwright）に切り替えています。
その分、初回だけブラウザ本体のダウンロードと起動時間が必要になります。

## 使い方（macOS/Linux）

```bash
./run.sh
```

## 出力物

| パス | 内容 |
|---|---|
| `output/report.html` | ブラウザで見るランキング表＋実行ログ（毎回上書き） |
| `output/summary_latest.json` | Claudeに貼って確認してもらう用の要約（上位20銘柄＋前回との比較） |
| `data/screener.db` | SQLite。実行のたびに履歴を蓄積（削除しない限り消えません） |
| `data/raw_pages/` | デバッグ用に、取得した生HTMLを保存（トラブル時の確認用） |
| `logs/screener_log.txt` | 実行時にコンソールへ表示される内容をそのまま追記保存したテキストログ |

## エラーが起きた・ウィンドウがすぐ閉じてしまった場合

`run.bat`のウィンドウが一瞬で閉じてしまった、何が起きたか確認できなかった、
という場合でも、**画面に表示される内容は必ず`logs/screener_log.txt`にも
そのまま保存されます**（エラー発生時のトラブルの詳細=Pythonのエラー内容も含む）。
このファイルをテキストエディタで開くか、そのままClaudeとの会話に貼り付けて
相談してください（2MBを超えると古い部分は自動的に切り詰められます）。

## 信用取引（需給）データのキャッシュ

候補銘柄1件ごとに個別ページ(`kabutan.jp/stock/?code=...`)を取得して信用取引データを
読みに行きますが、信用残は株探でも**週次**でしか更新されないため、毎回180件超すべてを
取り直すのは非効率です。そこで `data/screener.db` 内に `credit_cache` テーブルを持ち、
**取得から6日以内のデータはキャッシュを再利用**して株探への再アクセスをスキップします
（`kabutan_screener/config.py` の `CREDIT_CACHE_MAX_AGE_DAYS` で日数は変更可能）。

実行のたびにコンソールと`output/report.html`に「キャッシュ利用○件／新規取得○件」が
表示されるので、どれくらい節約できたか確認できます。信用残が更新されたはずなのに
反映されない、といった場合は次のようにキャッシュを無視して全銘柄を再取得できます。

```bash
python screener.py --refresh-credit
# または
run.bat --refresh-credit   (Windows)
./run.sh --refresh-credit  (macOS/Linux)
```

なお、ファンダメンタルズ／テクニカルのランキング一覧（候補選定そのもの）は
日々の株価で順位が変わるため、こちらは毎回取得し直します。

## スコアの算出方法

各指標を候補銘柄集団内でのパーセンタイル順位（0〜100点、高いほど良い）に変換し、
以下の重みで合成しています（Claudeとの会話で決めた方式と同じです）。

- **ファンダメンタルズ 40%**: 連続増益期数35% + 今期予想増益率40% + 増益期間平均増益率25%
- **テクニカル 35%**: 25日線カイリ率25% + 75日線カイリ率35% + 200日線カイリ率40%
- **割安度 10%**: PERの低さ（低いほど加点）
- **需給 15%**: 信用倍率（信用買い残÷売り残、低いほど加点）。売り残ゼロの
  「買い長」銘柄は、直近の信用買い残の増減率から
  `max(15, min(65, 50 - 増減率(%)×0.5))` で代替評価します。

候補条件: 通期営業利益が3期以上連続増益 **かつ** 25日・75日・200日移動平均線が
すべて上向き（両方のランキングに共通して登場する銘柄のみ）。

## kabutan.jpのページ構成が変わった場合

このスクリプトはCSSのクラス名ではなく、**見出しセルの文字列**（「コード」「銘柄名」
「株価」など）を手がかりにテーブルを探すようにしてあるため、多少のレイアウト変更には
耐えられるはずです。それでも動かない場合は:

1. `data/raw_pages/` に保存された生HTMLを開いて、実際の見出し文字列を確認する
2. `kabutan_screener/scraper.py` の `*_HEADER_ALIASES` に、実際の見出し文字列を追加する
3. `output/report.html` の実行ログや、コンソールに表示されるエラーメッセージも手がかりになります

わからない場合は、そのエラーメッセージと `data/raw_pages/` の該当HTMLをClaudeに見せて
相談してください。

## 定期実行したい場合

Windowsのタスクスケジューラに `run.bat`（および後述の `run_volume.bat`）を登録すれば、
毎日決まった時間に自動実行できます（このリポジトリ自体には自動実行の仕組みは含めていません。
手動 or お好みのスケジューラで実行してください）。

# 出来高急増ウォッチ（別ツール: volume_watch.py / run_volume.bat）

出来高（売買が成立した株数）が直近で急に増えているのに、株価はまだあまり動いていない
銘柄を探すためのツールです。「出来高が増える→やがて株価も動く」ことが多いという
経験則に基づき、株価が動く前の「物言わぬ買い集め」段階の銘柄を見つけることを狙います。

**長期上昇候補スクリーナーとは完全に別物**です（別のデータベースファイル、別のレポート、
別の起動スクリプト）。業績や需給は見ておらず、出来高と株価だけを見ています。

## 使い方

- Windows: `run_volume.bat` をダブルクリック（初回はscreener同様、venv作成・
  Chromiumダウンロードが走ります。`run.bat`と同じvenvを共有するため、
  両方とも一度実行していれば2回目以降のセットアップは不要です）
- macOS/Linux: `./run_volume.sh`

**毎営業日、続けて実行することが前提**のツールです。実行するたびにその日の出来高
ランキングを`data/volume_watch.db`に1回ぶん蓄積し、直近5営業日ぶん（実行した日ベース。
土日祝日をまたいでも自動的につじつまが合います）の最も古い日と最新の日を比較して、
出来高が急増した銘柄を検出します。**実行回数が少ないうち（2回未満）は「データ蓄積中」
と表示され、検出は行われません。**

## 出力物

| パス | 内容 |
|---|---|
| `output/volume_report.html` | ブラウザで見る候補一覧＋実行ログ（毎回上書き） |
| `output/volume_summary_latest.json` | Claudeに貼って確認してもらう用の要約 |
| `data/volume_watch.db` | SQLite。長期候補スクリーナーの `data/screener.db` とは別ファイル |
| `logs/volume_watch_log.txt` | 実行ログ（`logs/screener_log.txt`とは別ファイル）。エラー時はこちらも確認してください |

## 検出条件

- **出来高急増・株価横ばい候補**: 比較ウィンドウ内の最古日→最新日で、出来高が
  **2倍以上**（`config.VOLUME_SURGE_RATIO`）に増えているのに、株価の変化が
  **±3%以内**（`config.VOLUME_PRICE_FLAT_PCT`）に収まっている銘柄
- **ランキング新規浮上銘柄**: 直近の出来高ランキングに初めて登場した銘柄（比較対象が
  ないため倍率や株価変化は計算できませんが、急に出来高が増えた可能性が高い銘柄として
  参考表示します）

しきい値や比較する営業日数（既定5営業日）は `kabutan_screener/config.py` の
`VOLUME_SURGE_RATIO` / `VOLUME_PRICE_FLAT_PCT` / `VOLUME_LOOKBACK_RUNS` で変更できます。

## 出来高ランキングのURLについて（★重要・要確認★）

`kabutan_screener/config.py` の `VOLUME_RANKING_URL` は、実際にブラウザでkabutan.jpに
アクセスして確認したものではなく、**未確認の暫定値**です。実行してエラーになる場合や、
明らかにおかしい銘柄が出てくる場合は、以下の手順で正しいURLを確認し、設定を直してください。

1. ブラウザでkabutan.jpを開き、「ランキング」等から出来高（売買高）ランキングのページを探す
2. そのページのURLをコピーし、`kabutan_screener/config.py` の `VOLUME_RANKING_URL` に貼り付ける
3. `data/raw_pages/volume_page1.html` に保存された生HTMLも、見出し名の確認に使えます
   （見出しが見つからない場合、その旨のエラーメッセージが表示されます）
